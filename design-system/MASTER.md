# 林奇基本面研究设计系统

版本：3.0（2026-09-05，用户已批准UI优化需求）
生成方法：UI-UX-Pro-Max（设计系统检索＋颜色、字体、图表、React 可访问性专项检索）  
适用范围：公司研究、财务趋势、估值判断、规则审计、来源追溯

## 1. 产品定位

- 产品类型：面向个人投资者的单公司基本面研究工具，不是交易软件，也不是课程或书籍导读。
- 核心任务：输入股票代码，确认公司与数据范围，依次查看估值、增长、负债、现金流和原始依据。
- 用户假设：用户可能从未读过彼得·林奇，也不熟悉财务术语。界面必须先讲“看什么、为什么”，再提供公式与出处。
- 主要设备：桌面优先，兼容平板和手机；键盘、鼠标和触控均可操作。
- 失败成本：公司识别错误、报告期或单位混淆、缺失证据被当作正常，以及计算无法追溯。
- 必备状态：等待代码、加载、部分数据、完整数据、无证据、不适用、错误、扩展分析未配置、用户未确认。

## 2. 设计方向

方向名称：Market Ledger（亮色金融研究台）

- 气质：专业、现代、理性、安静。参考 TradingView 的信息层级、紧凑控制和数据可扫读性，不复制其交易界面。
- 视觉变异度：4/10。靠网格、数字、分隔线和少量深色锚点建立辨识度，不靠装饰。
- 动效强度：2/10。只有状态切换、弹层和悬浮反馈使用短动效。
- 信息密度：7/10。首屏清晰，结果页紧凑；高级内容按需展开。
- 主模式：亮色。冷灰画布、白色研究面板、深海军蓝文字、金融蓝主操作。
- 识别性结构：顶部“研究对象栏”常驻公司、市场、报告期和数据状态；内容采用研究账页式分区，不堆叠悬浮卡片。
- 语义原则：蓝色表示操作和当前选中；青绿色表示正向或已验证；琥珀只用于谨慎和缺失；红色只表示风险与失败。

## 4. 字体与数字

UI-UX-Pro-Max 推荐金融产品使用 IBM Plex Sans，中文产品推荐 Noto Sans SC。为避免字体网络加载影响首屏，采用本地系统等价组合：

```text
标题/界面："Segoe UI", "Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", sans-serif
数字："Cascadia Mono", "SFMono-Regular", Consolas, monospace
```

| 角色          | 字号/行高 | 字重    |
| ------------- | --------- | ------- |
| Display       | 30/39     | 650     |
| Page title    | 22/30     | 650     |
| Section title | 17/25     | 650     |
| Body          | 14/22     | 400     |
| Body strong   | 14/22     | 600     |
| Compact body  | 13/20     | 400/600 |
| Caption       | 12/18     | 400/600 |
| KPI           | 24/30     | 650     |

- 财务数字使用等宽数字 `font-variant-numeric: tabular-nums`。
- 中文正文不得低于 12px；关键说明保持 14px 以上。
- 英文只保留代码、市场缩写和必要术语，不用全大写英文作装饰性眉题。
- 标题短、直接、可扫描；不使用营销式口号和拟人化表达。

## 5. 网格、形状与层级

- 基础间距：4px；常用序列 4、8、12、16、20、24、32、40。
- 桌面页面边距 24px，平板 16px，手机 12px；主内容最大宽度 1680px。
- 桌面采用 12 列网格；主分析区 8 列，说明或依据区 4 列。
- 控件高度：紧凑 32px、标准 38px、触控 44px；表格行 40–44px。
- 圆角：控件 5px，面板 7px，弹层 8px。禁止所有内容都做大圆角卡片。
- 面板使用 1px 浅边框；默认无阴影。仅弹层使用 `0 16px 40px rgba(15, 23, 42, .14)`。
- 不使用渐变、玻璃拟态、发光边缘、装饰网格或纸张质感。

## 6. 信息架构

### 未查询

1. 顶栏：产品名、主要页面、数据来源说明。
2. 研究启动区：股票代码输入是唯一主操作。
3. 结果预告：用“公司与报告、四项判断、原始依据”解释查询后能得到什么。
4. 新手说明：用一句话解释林奇方法——通过增长、估值、负债和现金流判断公司质量，不要求阅读原著。

### 已查询

1. 固定顶栏：品牌、紧凑股票搜索、章节导航；总高不超过112px。
2. 公司栏：代码、市场、报告期、实际覆盖、行情日期、价格，以及辅助评分与证据覆盖入口。
3. 市场概览：PE、PB及两种每股净现金分组；窄屏两列，避免长条堆叠。
4. 最新报告对比：收入、净利润和EPS，本期、上年同期、上一期、同比及环比并列。使用现有数据，增长仅展示、不计分。
5. 历史财务：年度与Q1–Q4/H1–H2分别组织，原始值与同比相邻；图表保留表格替代视图。
6. 资产负债、规则与依据：保留原有计算和确认操作，公式与来源按需展开。
7. 数据覆盖、官方报告及补充研判：次级内容折叠，详细错误与缺失原因保留可达。

本版具体实施要求见同目录 `UI优化需求与案例参考.md`。视觉参考采用Stock Analysis的财务表格、Koyfin的概览层级及TIKR的期间组织；不引入外部财务数据。

## 7. 核心组件

### `AppHeader`

- 白色顶栏，左侧深海军蓝品牌锚点；当前导航以蓝色文字和底边双重标识。
- 产品名使用“林奇基本面研究”，副标题使用“官方财报 · 估值 · 财务质量”。

### `ResearchStarter`

- 标题为“研究一家公司，从股票代码开始”。
- 输入控件有显式标签、格式示例、加载和错误状态；动态结果通过 `aria-live` 宣告。
- 说明查询流程，不承诺任何投资结论。

### `CompanyContextBar`

- 公司身份、市场、报告期和数据覆盖始终可见。
- 公司类型同时提供通俗解释；未确认时显示“待确认”，不使用内部术语替代解释。

### `DecisionSummary`

- 分数与覆盖率、正向、风险、证据不足数量并列；没有证据时显示“待评估”。
- 结论采用“现状＋原因＋下一步查看”的句式，不输出空泛评价。

### `MetricStrip` 与 `DataTable`

- 标签、值、单位和报告期同时可见；数字右对齐，空值为“—”。
- 最新期可强调，但不使用高饱和整行底色；表格容器自身滚动，页面不得横向滚动。

### `RuleRow` 与 `EvidenceDrawer`

- 状态图标＋规则名＋当前值＋结论＋详情入口。
- 状态必须带“正向、风险、证据不足、不适用”等文字。
- 公式、来源、页码和本期代入放在详情区，不能只存在于悬浮提示。

## 8. 文案系统

- 面向用户的一级词汇：公司概览、数据覆盖、估值与增长、财务质量、风险提示、原始依据、补充研判。
- 首次出现“彼得·林奇方法”时解释为：用增长、估值、负债和现金流检查公司质量。
- 避免主界面词汇：终端、证据门、锁定、模型判断、AI 建议、智能洞察、赋能、深度解读。
- 可验证的数据写事实；主观判断标注为“待确认”或“补充研判”。
- 扩展分析必须如实说明其性质，但不在主流程反复强调“AI”。推荐标题“补充研判（可选）”，说明“仅整理定性信息，不改变程序计算结果”。
- 错误信息包含：发生了什么、当前保留了什么、用户下一步可以做什么。

## 9. 交互、响应式与可访问性

- Hover/pressed/focus/selected/disabled/loading/error 均有明确状态；交互反馈 120–180ms。
- 键盘焦点使用 2px `--ds-focus` 外环；对话框管理焦点并在关闭后返回触发元素。
- 遵循 `prefers-reduced-motion`；减少动效时取消位移和缩放。
- ≥1280px：12 列工作台；768–1279px：摘要两列、研究面板单列；<768px：单列，重要操作高度 44px。
- 390px、768px、1440px 均不得出现页面级横向滚动。
- 表单使用显式 `label`；动态加载、成功或错误使用 `aria-live`；点击操作使用原生 `button` 或 `a`。
- 图表带单位、报告期、直接标签和表格替代视图；不单靠颜色区分系列。

## 10. 验收清单

- 用户未读过彼得·林奇也能理解查询流程、四项核心判断和结果入口。
- UI 明确为亮色金融研究工具，颜色克制，英文装饰和重复状态显著减少。
- 首屏可看到公司搜索、查询说明和结果结构；查询后公司、报告期、数据覆盖和关键指标在首屏可见。
- 加载、空、部分数据、错误、无证据和不适用状态可区分。
- 关键结论有文字状态；图表有表格等价视图；程序结果和补充研判边界清楚。
- 组件只使用语义令牌，没有新增字体或视觉依赖。
